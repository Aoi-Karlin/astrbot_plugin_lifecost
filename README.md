# 花费查询

按 AstrBot 自带的 `provider_stats` 统计模型花了多少钱。**只读**，不写任何数据。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/花费 查询` | 总览：今天、本月、预算剩余、日均与整月推算、按模型 |
| `/花费 每天` | 本月每天的花费（带条形图） |
| `/花费 模型` | 按模型拆分的明细 |

默认**只有管理员**能查（`access.admin_only`）。花费信息一般不适合公开给群成员。

## 配置

### 单价（`pricing`）

口径与模型厂商的报价单一致：**元 / 百万 token**。

| 项 | 说明 |
| --- | --- |
| `input_per_mtok` | 普通输入 |
| `cached_input_per_mtok` | **缓存命中**的输入 |
| `output_per_mtok` | 输出 |

三个都填 0 时金额显示为 0，只能看 token 数（此时卡片会提示「还没配单价」）。

⚠ 关于缓存输入：命中缓存的输入通常只要普通输入的 10% 甚至更低。这个插件把
它单独计价，就是为了**不把成本高估几倍**——这是各家账单里最大的一个坑。

⚠ `cached_input_per_mtok` 填 0 的意思是「缓存输入不单独计价」，也就是**算成免费**。
如果你的模型有缓存折扣，请务必填上真实价格，否则会**低估**花费。

### 预算（`budget`）

`monthly_budget` 填了才会显示「剩余」和进度条。填 0 表示不设预算。

### 显示（`display`）

`top_models` / `daily_days` 控制各列表显示几条，填 0 表示全部。

## 统计口径

- 只统计 `agent_type = "internal"`，与「生活频率」插件同口径，所以两个插件的
  本月金额能对上；
- 按 **UTC+8** 划分日界与月界（`ProviderStat.created_at` 存的是 UTC，
  查询边界会做换算）；
- **插件自己发起的 `llm_generate` 不在统计里**——AstrBot 只在内部 agent 跑完
  一轮时才写 `provider_stats`。所以这里统计的是「宿主侧对话消耗」，不是「全部
  token 消耗」。

## 测试

```bash
python -m pytest tests -q
```

其中 `test_query_real.py` 会用内存 SQLite **真的建表、插数据、跑 SQL**，
验证时区日界、`internal` 过滤、按模型/天分组。这几件事写错了不会报错，
只会让数字悄悄不对，所以值得用真库测。
